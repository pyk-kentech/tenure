# tenure 사용 설명서

tenure 는 구독 중인 Claude Code 와 Codex 를 함께 사용해, 두 에이전트가 **구현 · 리뷰 · 수정을 회차별로 주고받으며** 결과물을 완성하도록 돕는 작업 환경입니다. 이 문서는 데스크톱 앱을 기준으로 첫 실행부터 워크플로 구성까지 순서대로 설명합니다.

앱 안에서도 같은 내용을 따라 할 수 있습니다. 오른쪽 사이드바의 **플로** 탭에서 머리글의 **사용 안내**(학사모 아이콘)를 누르세요.

---

## 1. 준비

| 항목 | 내용 |
|---|---|
| 데스크톱 앱 | GitHub 릴리스(`pyk-kentech/tenure-desktop`)의 `tenure-windows-setup.exe` 를 설치합니다. 서명되지 않은 설치 파일이므로 Windows 경고가 표시되면 '추가 정보 → 실행'을 선택합니다. |
| Claude Code | `claude` 명령이 설치되어 있고 로그인된 상태여야 합니다. |
| Codex | `codex` 명령이 설치되어 있고 `codex login` 으로 로그인된 상태여야 합니다. |
| 프로젝트 | git 저장소인 폴더를 권장합니다. 회차마다 커밋이 남아 변경 내용을 추적할 수 있습니다. |

> tenure 는 `~/.claude`, `~/.codex` 같은 사용자 설정 파일을 수정하지 않습니다. 상태 표시에 필요한 설정은 실행할 때마다 인자로 전달합니다.

---

## 2. 첫 플로 실행 (모의 실행)

처음에는 **모의 실행**으로 전체 과정을 확인하는 것을 권장합니다. 모의 실행은 실제 에이전트를 호출하지 않으므로 구독 사용량이 발생하지 않습니다.

1. 왼쪽 목록에서 작업공간을 선택합니다. 작업공간마다 독립된 git 워크트리에서 실행되므로 다른 작업과 섞이지 않습니다.
2. 오른쪽 사이드바에서 **플로** 탭을 엽니다.
3. **새 플로**를 누릅니다.
4. 과제를 입력합니다. 예: `할 일 목록 CLI 를 만든다. 추가 · 완료 · 목록 명령을 지원한다.`
   요구 사항을 구체적으로 적을수록 리뷰가 정확해집니다.
5. 진행 방식을 고릅니다(아래 표 참고).
6. **모의 실행**을 선택하고 **시작**을 누릅니다. 1분 안에 끝납니다.

| 진행 방식 | 내용 | 적합한 경우 |
|---|---|---|
| 자동 선택 | 과제를 보고 아래 방식 중 하나를 고릅니다. | 대부분의 경우 |
| 빠른 진행 | 한 에이전트가 구현하고 다른 에이전트가 간단히 리뷰합니다. 문제가 있을 때만 수정 회차를 진행합니다. | 요구 사항이 분명한 작업 |
| 경쟁 초안 | 두 에이전트가 각자 구현하고 서로 리뷰한 뒤 우수안을 채택합니다. | 접근 방법이 여러 가지인 작업. 비용은 빠른 진행의 약 두 배 |
| 설계 토론 | 설계를 먼저 토론해 합의한 뒤 구현과 교차 리뷰를 진행합니다. | 큰 설계 결정이 필요한 작업 |

실제 작업에서는 **모의 실행을 해제**한 뒤 시작하세요. 이때부터 구독 사용량이 발생합니다.

## 3. 실행 기록 읽기

플로가 시작되면 패널에 회차별 기록이 표시됩니다.

- **결과 요약**: 플로가 끝나면 만든 것, 실행 방법, 테스트 결과, 확인할 사항이 정리됩니다.
- **회차 기록**: 구현 → 테스트 → 리뷰 → 수정이 회차 번호와 함께 표시됩니다. 항목을 펼치면 에이전트의 응답을, 오른쪽 아이콘을 누르면 탭에서 크게 볼 수 있습니다.
- **판정**: 리뷰마다 '승인' 또는 '수정 요청'이 표시됩니다. 승인되면 플로가 끝나고, 상한까지 승인되지 않으면 '미승인 종료'로 끝납니다. 미승인으로 끝난 플로는 **이어서 실행**으로 회차를 늘려 계속할 수 있습니다.
- **중지**: 진행 중인 플로는 언제든 중지할 수 있고, 중지된 지점부터 이어서 실행할 수 있습니다.
- **그래프로 보기**: 워크플로 그림 위에 단계별 진행 상황을 표시합니다(5.5 참고).

진행 상황은 화면 상단의 **상태 창**에서도 확인할 수 있습니다. 승인 대기나 완료처럼 확인이 필요한 상황이 생기면 잠시 펼쳐져 알려 줍니다.

## 4. 변경 사항 검토

끝난 플로에서 **변경 사항 검토**를 누르면, 플로가 시작된 시점부터 바뀐 파일 전체가 좌우 비교 화면으로 열립니다.

- 왼쪽 파일 목록에서 파일을 고르고, 확인한 파일에는 확인 표시를 남깁니다.
- 줄마다 메모를 남긴 뒤 **tenure 플로로 보내기**를 누르면, 메모를 반영하는 수정 회차가 시작됩니다.
- 경쟁 초안 플로는 초안마다 브랜치가 따로 있으므로, 패널의 경쟁 초안 영역에서 초안을 비교하고 채택합니다.

## 5. 워크플로 편집기

플로 패널의 **워크플로**를 누르면, 어떤 역할이 어떤 단계를 맡을지 노드로 구성하는 편집기가 열립니다.

### 5.1 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | 시작할 템플릿, 자동 정렬, 검사, 저장, 저장 이름과 위치 |
| 왼쪽 | 추가할 수 있는 역할 · 단계 · 제어 노드 목록 |
| 가운데 | 노드를 배치하고 연결하는 캔버스 |
| 오른쪽 | 선택한 노드의 설정 |

### 5.2 노드

- **역할 노드**(왼쪽 열): 어떤 에이전트(claude · codex)가 어떤 모델과 추론 강도로 일할지 정합니다. 머리글 색이 에이전트를 나타내며(claude 주황, codex 청록), 역할마다 추가 지시문을 둘 수 있습니다.
- **단계 노드**: 무엇을 할지 정합니다. 머리글에 종류와 아이콘이 표시되고, 아래 행에 역할 항목과 설정값이 나열됩니다.

| 단계 | 내용 | 역할 항목 |
|---|---|---|
| 코드 탐색 | 프로젝트를 읽고 이후 단계에서 참고할 메모를 남깁니다. | 탐색 담당 |
| 설계 토론 | 제안자가 설계안을 쓰고 서로 비평한 뒤 종합자가 DESIGN.md 로 정리합니다. | 제안자(1~2), 종합자 |
| 구현 + 리뷰 | 구현자가 코드를 쓰고 리뷰어가 검토하며, 승인될 때까지 수정 회차를 반복합니다. 경쟁 상대를 연결하면 경쟁 초안이 됩니다. | 구현자, 리뷰어(1~3), 경쟁 상대, 중재자 |
| 감사 | 승인 이후 전체 변경 사항을 한 번 더 검토합니다. | 감사자(1~3) |

### 5.3 연결

- **담당 지정**: 역할 노드 오른쪽의 연결점을 단계 노드 왼쪽의 항목(구현자, 리뷰어 등) 연결점으로 드래그합니다. 연결선은 에이전트 색으로 표시됩니다.
- **진행 순서**: 단계 머리글 오른쪽의 연결점을 다음 단계 머리글 왼쪽의 연결점에 연결합니다. 순서 연결선 위로 작은 빛이 진행 방향을 따라 이동합니다.
- 새 단계를 추가하면 마지막 단계 뒤에 자동으로 연결됩니다.

### 5.4 제어 노드 (분기 · 추가 수정 · 병렬 실행)

| 노드 | 내용 |
|---|---|
| 분기 | 직전 결과에 따라 '예' 또는 '아니오' 경로로 진행합니다. 조건: 승인 여부, 테스트 통과 여부, 감사 이상 없음 여부 |
| 추가 수정 | 완료된 구현을 이어받아 수정 · 테스트 · 리뷰를 지정한 횟수(1~5)만큼 더 진행합니다. 다른 구현자 · 리뷰어를 지정할 수 있습니다. |
| 병렬 실행 | 코드 탐색 · 감사처럼 읽기 전용 단계를 동시에 실행한 뒤 '다음' 경로로 진행합니다. 파일을 수정하는 단계는 병렬로 둘 수 없습니다. |

앞 단계로 연결선을 되돌리면 **반복 구간**이 됩니다. 되돌아가는 선은 주황색 점선으로 표시되며, 노드마다 **최대 반복 횟수**(1~5)를 넘으면 그 자리에서 종료합니다. 구현 + 리뷰와 설계 토론은 한 번만 실행됩니다.

예: 구현 + 리뷰 → 분기(승인 여부) → 아니오: Codex 가 추가 수정 2회 → 분기로 되돌아감(최대 2회) / 예: 병렬 실행으로 감사 두 개를 동시에 진행

### 5.5 실행 보기

플로 패널에서 실행을 선택하고 **그래프로 보기**를 누르면, 그 실행이 사용한 워크플로가 편집기에 열리고 단계마다 상태가 표시됩니다.

| 표시 | 의미 |
|---|---|
| 파란 테두리와 깜빡이는 점 | 진행 중 |
| 초록 테두리와 체크 | 완료 |
| 빨간 테두리 | 실패 |
| 흐린 노드 | 도달하지 않음 |

- 실제로 지나간 연결선은 밝게, 지나가지 않은 연결선은 흐리게 표시되며, 지금 들어가는 단계로 향하는 선은 빛이 빠르게 이동합니다.
- 단계에 마우스를 올리면 진행 내용이 표시됩니다. 구현 + 리뷰와 추가 수정은 회차별 판정 · 막는 지적 수 · 테스트 결과, 감사는 감사자별 결과, 분기는 회차별 결정을 보여 줍니다.
- 진행 중인 플로는 2초마다 갱신됩니다. **이 구성으로 편집**을 누르면 일반 편집 화면으로 바뀝니다.

### 5.6 검사와 저장

- **검사**는 엔진과 같은 규칙으로 구성을 확인합니다. 비어 있는 역할 항목, 시작 단계에서 도달할 수 없는 단계, 잘못된 병렬 구성 등을 알려 줍니다.
- **저장 위치**
  - 이 프로젝트: `<작업공간>/.tenure/workflows/<이름>.toml`
  - 내 템플릿: `~/.tenure/workflows/<이름>.toml`
- 저장한 워크플로는 **새 플로** 양식의 진행 방식 목록에 표시됩니다. 같은 이름이 있으면 '덮어쓰기'를 선택해야 저장됩니다.

### 5.7 워크플로 파일 형식

편집기가 저장하는 파일은 사람이 직접 고칠 수도 있습니다. 순서대로만 진행하는 워크플로는 단계를 나열하고, 분기나 반복이 있으면 `next` · `yes` · `no` · `branches` 로 연결을 적습니다.

```toml
name = "rescue"
description = "구현 → 승인되지 않으면 Codex 가 추가 수정 → 승인되면 감사 두 개를 병렬로"

[roles.dev]
agent = "claude"

[roles.rev]
agent = "codex"

[roles.fixer]
agent = "codex"

[roles.aud]
agent = "claude"

[[steps]]
kind = "build"
id = "build"
implementer = "dev"
reviewers = ["rev"]
max_review = 1

[[steps]]
kind = "branch"
id = "ok"
check = "approved"      # approved | tests_pass | audit_clean
yes = "checks"
no = "rescue"
max_visits = 2

[[steps]]
kind = "continue"
id = "rescue"
implementer = "fixer"
reviewers = ["aud"]
rounds = 2
next = "ok"

[[steps]]
kind = "parallel"
id = "checks"
branches = ["a1", "a2"]
next = "end"

[[steps]]
kind = "audit"
id = "a1"
roles = ["aud"]

[[steps]]
kind = "audit"
id = "a2"
roles = ["rev"]
```

## 6. 그 밖의 기능

| 기능 | 내용 |
|---|---|
| 지휘자 + 작업자 중계 | 새 작업공간을 만들 때 선택합니다. 지휘자 Codex 는 파일을 수정하지 않고, 작업자 Codex 에게 회차마다 작업을 맡기고 결과를 확인합니다. |
| SSH 원격 실행 | 작업공간의 실행 위치로 SSH 서버를 지정하면 터미널과 에이전트가 해당 서버에서 실행됩니다. |
| 에이전트 상태 표시 | 탭과 카드에 작업 중 · 입력 대기 · 완료가 표시됩니다. Codex 기본 계정은 터미널 제목을 기준으로 추정합니다. |
| 사용량 | 상태 표시줄에서 Claude · Codex 의 5시간 · 주간 사용량을 확인할 수 있습니다. |

## 7. 자주 묻는 질문

**모의 실행과 실제 실행의 차이는 무엇입니까?**
모의 실행은 정해진 응답을 돌려주는 가상 에이전트로 전체 과정을 시연합니다. 파일 변경과 커밋은 실제로 일어나지만 내용은 연습용입니다. 실제 실행은 Claude Code 와 Codex 를 호출하며 구독 사용량이 발생합니다.

**커밋되지 않은 변경이 있으면 시작되지 않습니다.**
플로는 회차마다 커밋하므로, 기존 변경과 섞이지 않도록 시작을 막습니다. 변경을 커밋하거나, 그대로 진행하려면 '커밋되지 않은 변경이 있어도 시작'을 선택합니다.

**플로가 '미승인 종료'로 끝났습니다.**
리뷰 상한 안에 승인되지 않은 경우입니다. 마지막 리뷰를 확인한 뒤 **이어서 실행**으로 회차를 늘리거나, 변경 사항 검토에서 메모를 남겨 수정 회차를 요청합니다.

**워크플로 검사에서 '시작 단계는 하나여야 합니다'라고 표시됩니다.**
들어오는 연결선이 없는 단계가 둘 이상인 경우입니다. 첫 단계를 제외한 모든 단계가 앞 단계와 연결되어 있는지 확인하세요.
